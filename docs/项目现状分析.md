## 1. 项目概览

**校园生活平台**是一个面向高校师生的全功能服务聚合系统，覆盖以下业务域：

| 业务域 | 说明 |
| --- | --- |
| 🏷 二手交易 | 物品发布/搜索/下架，买家-卖家交易会话撮合（`items` + `trade_sessions`） |
| 💬 实时消息 | WebSocket 实时单聊/交易会话，多端在线、断线补偿、已读回执（`conversations`/`participants`/`messages`） |
| 📚 课程评价 | 课程库 + 星级评价（`courses` + `course_reviews`） |
| 🍚 食堂 | 食堂 → 摊位 → 菜品三级目录 + 菜品评价（`canteens`/`stalls`/`dishes` + `canteen_reviews`） |
| 💼 兼职 | 岗位发布/申请/录用管理（`jobs` + `job_applications`） |
| 📄 资源共享 | 学习资料上传/下载（`share_resources`） |
| 🤝 队友招募 | 竞赛/项目组队（`teams` + `team_members`） |
| 🚨 举报 | 用户/物品/消息/评论/资源举报工单 + 处理流水（`reports` + `report_logs`） |
| 👤 账户体系 | 邮箱/手机/自定义账号 + 密码统一登录，QQ/微信 OAuth，邮箱验证注册（`users`/`oauth_accounts`/`refresh_tokens`/`verification_codes`） |
| 🛡 管理后台 | 用户封禁/解封、举报处理、仪表盘、邮箱注册配置、物品管理（上下架/删除/发布审核开关）（`admin` 模块） |

**用户角色**：普通用户（可发布/交易/聊天/评价/申请）与管理员（登录 admin 后台，操作管理接口）。

**架构形态**：前后端分离的单体后端（模块化单体，不是微服务）。后端一个 FastAPI 进程承载全部 REST API + WebSocket，Celery worker 处理异步任务。

## 3. 系统架构与请求链路

```
浏览器(前端 SPA)
   │  /api/* (REST)                      /ws (WebSocket)
   ▼                                      ▼
┌─ Nginx (生产) / Vite dev proxy (开发: /api, /ws → :8000) ─┐
   ▼                                                        ▼
┌─────────────── FastAPI 单体 (uvicorn :8000) ────────────────┐
│  REST 路由 → 中间件(日志/限流/公开路径) → 模块 service → DB   │
│  WebSocket /ws → ConnectionManager → Redis Pub/Sub 广播      │
│  /metrics → Prometheus 指标                                  │
└───────┬──────────────────┬─────────────────┬───────────────┘
        ▼                  ▼                 ▼
  PostgreSQL/SQLite   Redis(6379)     MinIO(9000/9001) / 本地磁盘
                                      
Celery Worker（独立进程，-P solo，消费 email/notify/search/default 队列）
   └─ 邮件发送（✅ 唯一端到端可用）/ 站内通知 / Meilisearch 索引同步 / 交易摘要
      ⚠️ 2026-09-05 实测：仅 email 队列有真实 `.delay()` 调用方，
         notify / search / summary 三个任务代码完整但无触发点，详见 §8.4。
```

**请求链路（一次发布物品）**：
1. 前端先 `POST /api/files/presign`（带 Bearer token）拿 `object_key` + 预签名上传 URL，浏览器直传 MinIO（本地降级则 `POST /api/files/upload` 由后端落盘）。
2. `POST /api/items` 携带 `images: [{object_key, sort_order}]` 创建物品。
3. ⚠️ **更正（2026-09-05）**：旧版文档写的"创建后 Celery 任务 `index_item` 同步进 Meilisearch"**当前并未接线**——`search_sync` 任务全仓无任何 `.delay()` 调用方，Meilisearch 索引实际恒为空，`GET /api/items/search` 的真实流量 **100% 走 SQL LIKE 降级**。同步代码本身可用，补一行 `.delay()` 即可启用。
4. 其他用户通过 `POST /api/items/{id}/trade` 发起交易 → 创建 `TradeSession` + 自动建会话 → 双方经 WebSocket 实时聊天（交易抢占为条件 UPDATE 原子操作，见 §6.1）。

## 6. 数据库设计

## 7. 认证与授权

### 7.1 登录方式（全部支持，绑定到同一账户）

1. **账号密码登录**：`POST /api/auth/login`，body `{account, password}`。`account` 可以是 **自定义用户名 / 邮箱 / 手机号** 任一（后端统一查询）。兼容旧字段 `username`。
2. **手机验证码登录**：`POST /api/auth/send-code`（purpose=`login`）→ `POST /api/auth/phone-login` `{target, code}`。
3. **QQ/微信 OAuth**：`GET /api/auth/wechat/state`（或 qq）拿 state → 跳第三方 → `GET /api/auth/wechat/callback?code=&state=` 换 token。
4. **邮箱验证码注册**：`POST /api/auth/send-code`（purpose=`register`，target=邮箱）→ `POST /api/auth/email-register` `{email, password, code, nickname?}`。邮箱域名须在白名单（后台可配）。

### 7.2 补充绑定 / 解绑

- `GET /api/auth/bindings`：查看当前账户已绑定的 username/email/phone/oauth。
- `POST /api/auth/bind/email` `{email, code}`（验证码 purpose=`bind_email`）。
- `POST /api/auth/bind/phone` `{phone, code}`（purpose=`bind_phone`）。
- `POST /api/auth/bind/oauth` `{provider, code, redirect_uri?, state?}`。
- `DELETE /api/auth/unbind/email|phone|oauth`。
- **冲突策略**：若绑定目标已关联其他账户 → 拒绝绑定，返回 `code=40900`，message 明确提示"该邮箱/手机号已绑定其他账号"。解绑后可复用。不会自动合并账户。

### 7.3 JWT 流程

```
登录成功 → {access_token, refresh_token, token_type:"bearer", expires_in}
调用业务接口 → Header: Authorization: Bearer <access_token>
access 过期(40100) → POST /api/auth/refresh {refresh_token} → 新 token 对
登出 → POST /api/auth/logout（吊销 refresh；access 进入 Redis 黑名单至过期）
```

- `access_token`：短期（约 30 分钟），payload 含 `type=access`、`sub=user_id`。
- `refresh_token`：长期（约 7 天），`type=refresh`、`jti` 入库可吊销。
- 刷新时后端校验 refresh 的 jti 未吊销 → 旋转新对。
- **前端必须**：401 时静默刷新一次（刷新也失败则清登录态跳登录页）；token 存 localStorage（可刷新保留）。

### 7.4 验证码

- 发送：`POST /api/auth/send-code` `{target, purpose}`，purpose 取值 `login` / `register` / `bind_email` / `bind_phone`。
- 校验：后端按 `target+purpose` 匹配，有发送间隔与次数限制（Redis 计数）。
- 前端 UI：发送按钮 60s 倒计时是常见做法（后端限流兜底）。

### 7.5 权限模型

- 接口分三层：**公开**（登录/注册/验证码/OAuth state/callback/health）、**登录**（业务接口，`Authorization: Bearer`）、**管理员**（`/api/admin/*`，校验 `users.username` 为内置管理员）。
- 管理员账户由 `app/modules/admin/service.py` 的 `ensure_seed` 按 `config/school.yaml` 的 `admin.bootstrap` 段（用户名/密码）种子写入，**不再硬编码**，生产由部署配置下发强密码；`/api/admin/*` 还需网关令牌（见 §管理员域），未携带有效令牌一律返回 404。
- `GET /api/admin/me` 返回管理员信息；普通用户调用 admin 接口返回 40300。

### 8.5 WebSocket 实时消息协议（`/ws`）

- **连接**：`ws://host/ws?token=<access_token>&since=<ISO8601>`（token 必填，`since` 用于断线补偿可选）。
- **鉴权失败**：服务器发 `{"event":"error","data":{"code":40100,...}}` 后关闭连接。
- **客户端 → 服务器**：
  - `{"event":"ping"}` → 服务器回 `{"event":"pong"}`
  - `{"event":"message:send","data":{"conversation_id","content","type"(0/1/2)}}` → 持久化并广播
  - `{"event":"message:read","data":{"conversation_id"}}` → 回执 `message:read_ack`
- **服务器 → 客户端**：
  - `{"event":"message:new","data":{"id","conversation_id","sender_id","type","content","created_at"}}`
  - `{"event":"message:read_ack","data":{"conversation_id","user_id"}}`
  - `{"event":"error","data":{"code","message"}}`
- **断线补偿**：重连带 `since` → 服务器补推该会话之后的消息（最多 100 条）。
- 多端在线支持（同一用户多连接）；Redis Pub/Sub 跨实例广播。

### 8.6 搜索（`core/search.py`）

- Meilisearch 索引：`items`（按标题/描述）、`users`。
- 接口 `GET /api/items/search?q=`、`GET /api/users/search?q=` 优先走 Meilisearch，未启用时降级 SQL LIKE。
- 搜索同步由 Celery 任务维护（创建/删除物品时）。

## 9. API 规范与约定

### 9.1 统一响应格式（**最重要约定，前端必须遵守**）

所有 REST 接口返回：

```json
{ "code": 0, "message": "ok", "data": { ... } }
```

- 成功 `code=0`。
- **业务错误也是 HTTP 200**，靠 `code` 区分，`message` 为可展示中文。前端拦截器判断 `code !== 0` 即业务失败。
- 仅网络层/异常层（如 500、429 限流、422 FastAPI 校验）会出现非 200 状态码。

### 9.2 错误码

| code | 含义 |
| --- | --- |
| 0 | 成功 |
| 40000 | 参数/业务错误（通用） |
| 40100 | 未认证（token 缺失/过期/吊销） |
| 40300 | 禁止访问（权限不足） |
| 40400 | 资源不存在 |
| 40900 | 冲突（绑定冲突等） |
| 42200 | 校验失败（Pydantic） |
| 42900 | 限流 |

### 9.3 分页约定

列表接口统一 query 参数：`page`（默认 1，≥1）、`page_size`（默认 20，≤100）。
`data` 形如 `{"total": n, "items": [...]}`（部分接口为数组，以 API_Reference 为准）。

### 9.4 鉴权头

```
Authorization: Bearer <access_token>
```

### 9.5 金额单位

**`price`/`salary` 单位一律为"分"（int）**，前端展示需 ÷100 并保留两位；提交也传分。

### 9.6 时间格式

ISO 8601 字符串（`datetime.isoformat()`），如 `2026-08-25T10:30:00+08:00`。

### 11.3 三个值得关注的前端工程点

1. **401 并发合并刷新**（`services/api.ts`）：用 `isRefreshing` + `refreshPromise` 单例 Promise，保证多个请求并发 401 时**只触发一次刷新**，其余共享同一 Promise 并在成功后自动重放原请求；`softAuth` 模式让未读数等非关键请求刷新失败时**降级返回而非强制登出**，避免网络抖动误踢用户。

## 12. 前端对接要点（给 AI 的关键约束）

1. **统一响应拦截**：所有接口 `{code,message,data}`；`code===0` 成功，否则读 `message` 提示。HTTP 状态码不可信（业务错误是 200）。网络层错误（无响应）单独处理。
2. **401 处理**：拦截 `code===40100` → 尝试 `POST /api/auth/refresh`（带 refresh_token）→ 成功后重放原请求；刷新失败则清 token 跳登录页。refresh_token 也要过期，需兜底登出。
   **并发要点**：多个请求同时 401 时必须**合并为一次刷新**（`api.ts` 用单例 `refreshPromise` 实现），否则后到的刷新会让先到的请求拿到已失效的旧 token。
3. **Token 存储**：`access_token` + `refresh_token` 存 localStorage。请求层统一加 `Authorization: Bearer <access_token>`。
   （注：现行实现是 `services/api.ts` 的 `fetch` 封装，**非 axios**——旧版文档此处描述有误。）
   管理员另有一套独立的 `admin_token` + `X-Admin-Gateway`，与普通用户令牌**互不污染**。
4. **金额**：所有 price/salary 是"分"，展示 ÷100，格式 `¥12.50`。
5. **枚举映射**：§6.2 的状态值在 UI 全部转中文标签 + 颜色（如 item.status 0=上架绿色，1=下架灰，2=已售橙，3=保留蓝）。
6. **图片/文件上传**：
   - 先 `POST /api/files/presign`（form：prefix=items/shares/avatars, filename）拿 `{object_key, upload_url, direct}`。
   - `direct:true` → PUT 文件到 `upload_url`（MinIO 直传）；`direct:false` → `POST /api/files/upload`（FormData：key+file）。
   - 提交业务（发布物品）时传 `object_key` 而非 URL。展示图片需重新 `presign` 拿下载签名 URL。
7. **WebSocket**：
   - 登录后连 `/ws?token=<access_token>`；收 `message:new` 更新聊天列表。
   - 心跳：每 30s 发 `{"event":"ping"}`，收 `pong` 保活；断线按 **1s → 30s 指数退避**重连。
   - **断线补偿（2026-09-05 更新）**：优先传 **`last_seq`**（后端 Redis ZSet 单调序号，补发区间 `(N, +inf]`，精确不重不漏）；
     旧参数 `since`（时间戳）**已不推荐**——同一时间刻度内的多条消息无法区分，用 `>` 会丢消息、放宽成 `>=` 又重复推。详见 `message/seq.py` 模块 docstring。
   - 发消息：`{"event":"message:send","data":{...}}`；自己发的消息不依赖广播回显，可乐观插入。
   - 会话详情用 REST `GET /api/messages/conversations/{id}` 拉历史。
8. **分页**：列表页用 `page`/`page_size` 参数，响应 `data.total`/`data.items`。
9. **管理员域**：`/api/admin/*` 受网关保护——需先在 `/api/admin/discover` 用部署下发的网关密钥换取短时令牌，并携带 `X-Admin-Gateway` 头；未携带有效令牌一律返回 404。管理员凭证由 `config/school.yaml` 的 `admin.bootstrap` 配置下发（不再固定 admin/admin123）。普通前端不暴露 admin 入口与敏感路由。
10. **可用性设计**：Meilisearch/MinIO 未部署时后端会自动降级（SQL 搜索/后端落盘），前端无需感知，但**搜索接口**在没有 Meilisearch 时返回的是 SQL 结果结构（`items` 数组），需与 Meilisearch 返回兼容处理（都以 items 数组为准）。

### 13.2 生产（deploy/docker-compose.yml）

服务：`api`（uvicorn + 后端）、`worker`（celery，挂 `config:/app/config:ro`）、`redis`、`minio`、`meilisearch`、`postgres`、`nginx`、`prometheus`、`grafana`。环境变量 `DB_URL=postgresql+asyncpg://...`、`REDIS_URL`、`MINIO_*`、`MEILI_*` 在 compose 中配置。首次启动自动建表 + seed 管理员。

### 13.3 关键环境变量（backend/.env 或 compose）

| 变量 | 说明 |
