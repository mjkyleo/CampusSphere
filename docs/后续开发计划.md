## 2. 总体架构目标

```
┌────────────────────────────────────────────────────────────┐
│ 浏览器（用户）                                               │
│   http://localhost:5173  →  frontend           │
│   ws://localhost:5173/ws  （同源，无需 CORS）                │
└───────────────────────────┬────────────────────────────────┘
                            │ REST /api/*  +  WS /ws  (upgrade)
                            ▼
┌────────────────────────────────────────────────────────────┐
│ Express 代理层（server.ts）                                  │
│   - /api/ai/*、/api/health → 本地处理                        │
│   - 其余 /api/* → http://127.0.0.1:8000                     │
│   - /ws        → ws://127.0.0.1:8000/ws（携带 token/since）  │
└───────────────────────────┬────────────────────────────────┘
                            │
                            ▼
┌────────────────────────────────────────────────────────────┐
│ FastAPI 后端（uvicorn :8000）                                │
│   - 统一响应 {code, message, data}，业务错误 HTTP 200        │
│   - JWT Bearer 认证；40100 触发前端刷新流程                   │
│   - WS 协议：ping/pong/message:send/message:new/read/ack    │
│   - CORS 白名单（加固项 T1.2）                               │
└────────────────────────────────────────────────────────────┘
```

**两种访问模式**：
1. **推荐（同源代理）**：用户访问 `:5173`，一切请求经 Express 转发，无跨域问题。
2. **直连模式**：开发调试时前端直接访问 `:8000`，此时依赖后端 CORS 白名单（T1.2 必须放行 `http://localhost:5173`）。

**T1.2 后端 CORS 收窄为白名单**
- 依赖：无（可并行）
- 目标：`cors_origins` 从 `["*"]` 改为显式白名单，兼顾安全与直连调试。
- 涉及文件：
  - `backend/app/core/config.py`（`cors_origins` 默认值）
  - `backend/.env`（新增 `CORS_ORIGINS`，如 `http://localhost:5173,http://127.0.0.1:5173`）
  - `backend/app/main.py`（确认 `allow_credentials=True` 与白名单匹配）
- 实施要点：
  1. 白名单默认：`http://localhost:5173`、`http://127.0.0.1:5173`；生产环境追加正式域名。
  2. 注意：`allow_credentials=True` 时 `allow_origins` **不能**含 `"*"`（浏览器规范限制）；JWT 走 Authorization 头，不使用 Cookie，但统一收窄更安全。

### Phase 2　WebSocket 实时通信接入（主体已完成，补齐收尾）

**T2.1 断线补偿落地（MessageCenter）**
- 依赖：T0.2
- 目标：重连后不丢消息，`since` 补偿真正在 UI 层生效。
- 涉及文件：`frontend/pages/MessageCenter.tsx`
- 实施要点：
  1. 确认后端 `/ws?since=` 已按 `created_at` 回放（现状：已支持，见 `docs/项目现状分析.md` §WebSocket 协议）。
  2. `wsClient` 已在重连时自动携带 `since`（`lastMessageAt`）；MessageCenter 在 `onclose`→`onopen` 恢复后调用 REST `messages.list(since)` 拉取缺口并去重合并，避免依赖单次 WS 回放。
  3. 断线期间在会话顶部显示“连接已断开，正在重连…”状态条（`isConnected` 已由 hook 提供）。
- 验收：
  1. 断网 10s 内收到的消息，恢复后 5s 内出现且不重复。
  2. 会话窗口显示连接状态指示；断线时 UI 有明确提示。
  3. 心跳 30s 一次，无“僵尸连接”。

**T2.2 token 刷新后 WS 无缝重连**
- 依赖：T2.1（逻辑上）／A6（已实现刷新）
- 目标：`access_token` 过期刷新后，WS 会话以新 token 重连，不掉线丢失。
- 涉及文件：`frontend/context/AuthContext.tsx`、`services/api.ts`（refresh 流程）
- 实施要点：
  1. refresh 成功回调中调用 `wsClient.connect(newAccessToken)`（已有 `connect` 幂等逻辑：同 token 不重复建连）。
  2. 刷新失败（refresh_token 也过期）→ 登出 + `wsClient.disconnect()`。
- 验收：设置极短 `ACCESS_TOKEN_EXPIRE`（如 60s）压测：期间持续聊天不中断，会话内消息完整。

### Phase 5　兼容性与端到端验收

**T5.1 API 响应格式与错误码验收**
- 依赖：P1–P4
- 验收清单：
  1. 所有成功响应体为 `{code:0, message:"ok", data:...}`；前端 `request` 层按 `code` 判定，非 0 抛业务错误。
  2. 业务错误 HTTP 200 + body code（40100/40300/40400/40900/42200）在全局处理中正确映射（401 → 刷新重试一次 → 再失败登出）。
  3. 分页参数 `page/page_size(≤100)` → 返回 `{total, items}`；金额单位分；时间 ISO8601。

**T5.2 JWT 认证链路验收**
- 依赖：T2.2、T5.1
- 验收清单：
  1. 无 token 访问受保护接口 → `40100` → 前端跳登录。
  2. access 过期 → 静默刷新（并发请求合并为一次刷新）→ 重试成功。
  3. refresh 过期 → 登出清理 `wsClient.disconnect()` + 清空本地状态。
  4. WS 握手 token 校验失败返回 `error` 事件（对照协议）。

## 5. 兼容性硬约束（贯穿所有任务）

1. **响应格式**：永远 `{code, message, data}`；前端只信 `code===0`；业务错误走 HTTP 200 + code。
2. **JWT**：`Authorization: Bearer <access>`；40100 触发刷新；刷新并发合并；`ws?token=` 携带同一 access token。
3. **枚举**：以 `backend/app/common/enums.py` 为唯一事实源，前端 `types.ts` 数值必须一致（对照 §T5.3），改动枚举必须三处同步（后端、前端、docs）。
4. **金额**：一律“分”；展示 `/100`。
5. **分页**：`page`/`page_size(≤100)` → `{total, items}`。
6. **时间**：ISO8601 UTC。
7. **文件 key**：图片以 `object_key` 引用，展示统一走 `/files/{key}`（local）或预签名 URL（direct）。
8. **WS 协议**：事件名固定 `ping/pong/message:send/message:new/message:read/message:read_ack/error`；`since` 用 `created_at` ISO8601。

## 6. 风险与注意事项

| 风险 | 影响 | 缓解 |
|------|------|------|
| `cors_origins` 收窄后直连调试失败 | 开发受阻 | 白名单先加 localhost:5173/127.0.0.1:5173，.env 可覆盖 |
| WS 心跳被代理层超时中断 | 假断线 | 确认 Express `http-proxy` upgrade 超时配置（`proxyTimeout`），后端心跳 30s 与代理超时对齐 |
| direct 直传依赖 MinIO，本机已降级 local 磁盘 | 图片不可见 | 以 local 模式为准验收；部署时切换环境变量并回归 |
| 审核开关（T4.3）改动波及状态机/搜索/文档 | 连锁风险 | 开关默认关闭（发布行为与现在一致）；枚举/状态机/过滤三处同步评审后再开启 |
| 旧 Vue frontend/ 误启 | 双前端混乱 | T1.1 归档并更新文档 |
| mock fallback 掩盖真实后端问题 | 验收假阳性 | Phase 0 起后端必须真实可达；T5.4 全程关 mock |
