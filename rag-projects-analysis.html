二、基础 RAG（7个）

这类项目聚焦 RAG 核心流程的最小实现，适合入门学习和快速搭建原型。

1. simple-rag-workflow

入门零付费简历价值 2/5

用处：最精简的 RAG 入门实现，纯 Notebook 形式演示检索增强生成核心流程。

技术栈：LlamaIndex + Ollama (Llama 3.2) + Jupyter Notebook，无独立向量库。

亮点：7 个项目中代码量最少，零外部依赖，适合零基础理解 RAG 四步（加载→切分→嵌入→检索→生成）。

局限：无 UI、无向量库、无生产级组件，简历展示价值极低。

2. document-chat-rag

入门+零付费简历价值 3.5/5

用处：带 Web UI 的文档对话 RAG，支持文档上传和问答交互。

技术栈：LlamaIndex + Qdrant (Docker) + Ollama (Llama 3.3) + Streamlit。

亮点："本地 LLM + 生产级向量库 + Web UI"完整三件套，Qdrant 是 Rust 高性能向量数据库。

局限：嵌入模型未明确说明，README 较简略。

3. fastest-rag-stack

中级SambaNova 付费简历价值 3.5/5

用处：主打低延迟的文档对话 RAG，使用专用 AI 推理芯片加速。

技术栈：LlamaIndex + Qdrant + SambaNova (Llama 3.3 云推理) + Streamlit + SSE 流式。

亮点：唯一涉及专用 AI 硬件推理服务（SambaNova）的项目，差异化明显。

局限：SambaNova API 需申请，可及性有限；嵌入模型未说明。

4. github-rag ⭐

中级可零付费简历价值 4/5

用处：100% 本地运行的代码仓库问答 RAG——输入 GitHub 仓库地址，自动解析代码并支持语义问答。

技术栈：LlamaIndex + GitIngest (仓库→Markdown) + Ollama/OpenAI + HuggingFace 嵌入 + Streamlit。

亮点：唯一面向代码仓库场景的基础 RAG；GitIngest 自动结构化代码库；支持本地/云端 LLM 灵活切换。

局限：向量库使用 LlamaIndex 默认，未接入生产级向量数据库。

5. modernbert-rag

中级零付费简历价值 3.5/5

用处：文档对话 RAG，核心特色是使用微软 ModernBert 作为嵌入模型提升检索质量。

技术栈：LlamaIndex + ModernBert (HuggingFace) + Ollama (Llama 3.2) + Streamlit。

亮点：唯一明确指定嵌入模型的项目；ModernBert 在长文本检索上优于传统 BERT；聚焦"嵌入选型对 RAG 质量的影响"。

局限：需从 GitHub 源码安装 transformers，复现不稳定性高；未说明具体 ModernBert 变体。

6. llama-4-rag

入门+Cerebras 付费简历价值 3/5

用处：基于 Meta Llama 4 的文档对话 RAG。

技术栈：LlamaIndex + Cerebras API (Llama 4) + Streamlit + uv 包管理。

亮点：使用最新 Llama 4 模型；Cerebras 晶圆级引擎主打超低延迟；uv 包管理体现工程规范。

局限：README 极度简略（仅 270 token），嵌入模型和向量库均未说明，技术深度展示有限。

7. video-rag-gemini

入门Gemini 付费简历价值 3.5/5

用处：上传视频文件并与之对话，利用 Gemini 多模态能力直接理解视频内容。

技术栈：Google Gemini File API + Streamlit，支持 MP4/AVI/MOV/MKV/WEBM。

亮点：唯一多模态视频问答应用；功能完整（会话管理、流式响应、进度反馈）；README 最详尽。

局限：严格来说不是传统 RAG（无分块/嵌入/向量检索），而是端到端多模态理解；强依赖 Gemini API。

三、Agentic / 进阶 RAG（9个）

这类项目在基础 RAG 上引入 Agent 编排、智能路由、纠错检索、SQL 混合查询等进阶能力。

8. agentic_rag

中级FireCrawl 付费简历价值 4/5

用处：CrewAI 驱动的 Agentic RAG，文档检索不到答案时自动 fallback 到 Web 搜索。

技术栈：CrewAI + crewai-tools + Qdrant + FastEmbed + MarkItDown + FireCrawl + Streamlit；支持 DeepSeek-R1 或 Llama 3.2 本地运行。

亮点：文档检索 + Web 搜索的双路 fallback 机制；提供 DeepSeek 和 Llama 两种本地 LLM 入口；chonkie 语义分块。

局限：Web 搜索强依赖 FireCrawl API；README 较简短。

9. agentic_rag_deepseek

中级3个付费API简历价值 4/5

用处：企业级 Agentic RAG，将 GroundX 文档解析检索系统作为 CrewAI 自定义工具。

技术栈：CrewAI + GroundX (EyeLevel) + SERPER API + DeepSeek + Streamlit。

亮点：GroundX 专为复杂文档设计的解析检索（优于通用文本切分）；支持完全本地私有化部署；CrewAI Agent 多步推理。

局限：需配置 3 个 API Key；DeepSeek 模型具体用法 README 说明不足。

10. deploy-agentic-rag

入门+零付费简历价值 3/5

用处：100% 私有的 Agentic RAG API 服务，CrewAI + LitServe 构建可部署的推理端点。

技术栈：CrewAI + LitServe + Ollama (Qwen3)，Server-Client 架构。

亮点：完全本地私有化，零付费；LitServe 是轻量高性能推理服务框架；展示了 RAG 从脚本到 API 服务的部署能力。

局限：实现极简（README 仅 259 token），无向量库细节、无 UI，功能单薄。

11. firecrawl-agent ⭐

中级FireCrawl+OpenAI(可选)简历价值 4/5

用处：完整的 Corrective RAG（纠错 RAG）工作流：文档检索 → 相关性评估 → 不足时触发 Web 搜索 → 综合生成。

技术栈：LlamaIndex + FireCrawl + Milvus + FastEmbed (BGE-large-en-v1.5) + Streamlit；支持 OpenAI/Ollama/LMStudio。

亮点：仓库中最完整的 Corrective RAG 实现，含工作流架构图；相关性过滤机制提升回答准确率；Milvus 生产级向量库；多 LLM 提供商兼容。

局限：默认路径需 OpenAI + FireCrawl 双 API；本地 LLM 替代需自行配置。

12. rag-sql-router ⭐⭐

中级OpenRouter+Cleanlab简历价值 4.5/5

用处：智能路由 Agent——根据查询自动选择走向量库 RAG 检索还是 SQL 数据库查询，并对回答做可信度验证。

技术栈：LlamaIndex + Docling (IBM 文档解析) + Milvus (自托管) + Cleanlab Codex (回答验证) + OpenRouter (Qwen) + Streamlit + Notebook。

亮点：RAG + SQL 双引擎路由是差异化最强的设计；Cleanlab Codex（MIT 团队）提供自动响应验证、信任评分、SME 干预闭环，直击 Agent 输出可靠性痛点；Milvus 自托管展示运维能力；Notebook + App 双入口。

局限：依赖 OpenRouter 和 Cleanlab 两个付费服务；SQL 引擎部分细节 README 未展开。

13. fastest-rag-milvus-groq

中级Groq+Beam简历价值 3.5/5

用处：极致性能 RAG，宣称检索延迟 <15ms，使用二值量化 + Groq 高速推理。

技术栈：LlamaIndex + Milvus (Binary Quantization) + Groq (Kimi K2) + Beam (Serverless 部署) + Streamlit。

亮点：Milvus 二值量化索引大幅降低检索延迟和存储；Groq LPU 推理引擎速度极快；Beam 云原生 Serverless 部署。

局限：Groq 和 Beam 均为付费云服务；性能指标依赖特定硬件环境；功能较单一（纯速度优化）。

14. rag-with-dockling

中级零付费简历价值 3.5/5

用处：对 Excel/PPT/复杂版式文档构建 RAG，利用 IBM Docling 做高质量文档解析。

技术栈：LlamaIndex + IBM Docling (Reader + Node Parser) + Ollama (Qwen3) + HuggingFace 嵌入。

亮点：Docling 专为表格/PPT/版式文档设计，解析质量优于 PyPDF；全链路可本地运行零付费；Docling Node Parser 保留表格结构语义。

局限：README 极其简短（仅安装步骤），缺少运行示例和架构说明；Docling 是较新的库，API 可能变动。

15. trustworthy-rag

中级TLM+LlamaParse简历价值 4/5

用处：可信 RAG 系统，使用 Cleanlab TLM 为生成结果提供置信度评分和推理依据，解决幻觉问题。

技术栈：LlamaIndex + Cleanlab TLM + LlamaParse + HuggingFace 嵌入 + Streamlit (含可信分数 glow UI)。

亮点：核心差异化是 TLM 置信度评分——不仅给答案，还给可信程度和推理过程；直接回应 RAG 幻觉这一企业核心痛点；UI 对可信分数有视觉高亮。

局限：TLM 和 LlamaParse 均为托管 API，无本地替代；README 较简短。

16. chat-with-code ⭐⭐

高级OpenRouter+Cleanlab简历价值 4.5/5

用处：代码仓库自然语言问答系统，使用 Qwen3-Coder 专用代码模型生成回答，Cleanlab Codex 验证正确性。

技术栈：LlamaIndex + Milvus (Docker) + OpenRouter (Qwen3-Coder) + Cleanlab Codex + Streamlit + uv + Jupyter Notebook。

亮点：代码 RAG 是 AI 开发工具方向的核心场景；Qwen3-Coder 是最新专用代码模型；"生成→验证"闭环（Cleanlab Codex）极具差异化；Milvus 自托管 + uv 展示工程规范；Notebook + App 双入口完整度高。

局限：依赖 OpenRouter 和 Cleanlab 两个付费服务；纯本地复现需自行改造 LLM 层。

四、语音/音频 RAG（3个）

这类项目将语音/音频作为输入或交互模态，扩展 RAG 的感知边界。

17. rag-voice-agent

高级Cartesia+STT简历价值 4/5

用处：实时语音 RAG Agent，用户语音交互，系统实时完成 STT→RAG→TTS 全链路低延迟对话。

技术栈：双方案——①OpenAI STT + Cartesia TTS + LiveKit；②AssemblyAI + Ollama/Gemma3 + Cartesia + LiveKit。前端：LiveKit Agents Playground。

亮点：真正的实时语音交互（非录音→转写模式）；云端/本地 LLM 双路径；LiveKit 低延迟实时音频流；Cartesia 高质量自然语音合成。

局限：复现需多个付费 API；RAG 部分 README 未详细展开；环境配置复杂度高。

18. chat-with-audios

中级AssemblyAI简历价值 3.5/5

用处：对音频文件构建 RAG——先转写为文本，再建向量索引，实现音频内容语义检索问答。

技术栈：AssemblyAI (转写) + LlamaIndex + Qdrant (Docker) + SambaNova/Ollama + Streamlit。

亮点：音频→文本→RAG 完整垂直管线；AssemblyAI 支持说话人分离；Qdrant 高性能向量库；LLM 层支持 SambaNova 或本地 Ollama 切换。

局限：整体管线偏标准，差异化不够突出；README 较简短，缺少架构图。

19. multimodal-rag-assemblyai

中级AssemblyAI+OpenAI简历价值 4/5

用处：多模态 Agentic RAG——支持音频+文本数据摄入，用户语音提问，经转录→检索→双 Agent 编排后输出。

技术栈：CrewAI Flows + AssemblyAI + Milvus (Docker) + OpenAI (LLM+嵌入)。

亮点：端到端语音交互；CrewAI 双 Agent 分工（Research Agent 分析 + Response Agent 综合）；支持音频+文本多模态摄入；代码结构完整（docker-compose）。

局限：两个付费 API 依赖；OpenAI 同时做嵌入和 LLM，成本较高。

五、多模态 RAG（2个）

这类项目直接对图像/文档页面进行多模态理解和检索，不经过 OCR 转文本的中间步骤。

20. deepseek-multimodal-RAG

高级零付费(需GPU)简历价值 4/5

用处：基于 DeepSeek-Janus-Pro 的多模态 RAG，支持对含图像的文档（PDF）进行语义检索问答。

技术栈：DeepSeek-Janus-Pro (本地) + ColPali (视觉编码器) + Qdrant + fastembed + Streamlit + flash-attn。

亮点：全程本地运行零 API 费用；ColPali late-interaction 检索无需 OCR；Janus-Pro 原生多模态理解；代码完整（app.py + rag_code.py）。

局限：硬件门槛高（Janus-Pro 需 GPU 显存）；flash-attn 编译需 CUDA 环境；本地部署复现成本大。

21. Colivara-deepseek-website-RAG

中级ColiVara+Firecrawl简历价值 4/5

用处：面向网站的多模态 RAG——Firecrawl 抓取网页 → ColiVara 文档理解检索 → Janus-Pro 多模态生成回答。

技术栈：DeepSeek-Janus-Pro (本地) + ColiVara (文档检索) + Firecrawl (网页抓取) + Streamlit + streamlit-pdf-viewer + fastembed。

亮点：ColiVara 工业级文档解析检索（专为复杂文档优化）；"网页→结构化文档→多模态问答"全链路；PDF 查看器可溯源展示原文页面。

局限：两个第三方 SaaS 依赖增加复现成本；Janus 本地部署仍需 GPU。

六、MCP RAG（5个）

这类项目通过 MCP（Model Context Protocol）协议将 RAG 能力封装为标准工具，供 Cursor、Claude Desktop 等 MCP 客户端调用。

22. eyelevel-mcp-rag

入门GroundX简历价值 3/5

用处：MCP 服务器封装 GroundX 文档搜索能力，对复杂真实文档做 RAG 并通过 MCP 协议暴露。

技术栈：GroundX/EyeLevel + Python MCP SDK + uv。

亮点：专门针对复杂文档优化；以 MCP 标准协议封装，可直接接入 Cursor/Claude Desktop；项目极简。

局限：代码量极少（README 仅 297 token），主要是对 GroundX API 的 MCP 封装，深度有限。

23. llamaindex-mcp ⭐⭐

中级零付费简历价值 4.5/5

用处：用 LlamaIndex 构建本地 MCP 客户端——连接本地 MCP 服务器（暴露 SQLite 等工具），通过自然语言与工具调用 Agent 交互。

技术栈：LlamaIndex + Python MCP SDK (服务器+客户端双端) + SQLite + Ollama/OpenAI + uv + pyproject.toml。

亮点：唯一可完全本地运行且零付费的 MCP 项目；同时实现 MCP 服务器（SQLite 工具）和 MCP 客户端（LlamaIndex Agent），完整展示协议两端；SSE 传输模式；代码完整（server.py + ollama_client.ipynb）。

局限：示例场景（SQLite 查询）相对简单，需要自行扩展到更复杂的 RAG 场景。

24. mcp-agentic-rag

中级Bright Data简历价值 4/5

用处：MCP 驱动的 Agentic RAG（Cursor IDE 客户端）——Bright Data 抓取网页→存 Qdrant→MCP 服务器暴露→向量检索+Web fallback。

技术栈：Bright Data (SERP API) + Qdrant (Docker) + Python MCP SDK + Cursor IDE + Jupyter Notebook (建库)。

亮点：Cursor IDE 作为 MCP 客户端的实战案例；向量库检索 + Web 搜索 fallback 混合策略；Bright Data 代理级 SERP 抓取质量高。

局限：Bright Data 付费门槛较高；与项目 #25 架构高度相似（仅抓取工具不同）。

25. mcp-agentic-rag-firecrawl

中级Firecrawl简历价值 3.5/5

用处：与 #24 架构相同，网页抓取工具从 Bright Data 替换为 Firecrawl。

技术栈：Firecrawl + Qdrant (Docker) + Python MCP SDK + Cursor IDE + Jupyter Notebook。

亮点：Firecrawl 专为 LLM 优化（自动转 Markdown、JS 渲染、批量爬取），比 Bright Data SERP 更适合 RAG 数据摄入；API 配置更简单（仅需一个 Key）。

局限：与 #24 技术栈高度重复，差异化仅在抓取工具；作为独立项目展示价值有限。

26. mcp-video-rag

入门+Ragie简历价值 4/5

用处：基于 Ragie 的视频 RAG，通过 MCP 集成到 Cursor——支持视频摄入、语义检索、问答，并能根据查询自动生成视频片段。

技术栈：Ragie (video-RAG 专用服务) + Python MCP SDK + Cursor IDE + uv (Python 3.12+)。

亮点：唯一的视频 RAG 项目，差异化极强；3 个 MCP 工具设计（摄入/检索/生成视频片段）；"检索→自动剪片"全流程有创意；MCP 工具定义清晰，代码完整。

局限：核心能力完全依赖 Ragie SaaS，自建替代方案难度大。

七、评测与模型对比（3个）

这类项目不直接构建 RAG 应用，而是聚焦 RAG 系统的质量评估、可观测性和模型横向对比。

27. eval-and-observability

入门+OpenAI+Opik简历价值 3/5

用处：为 RAG 应用构建 E2E 评测与可观测性管道，使用 CometML Opik 追踪全链路表现。

技术栈：LlamaIndex + OpenAI + CometML Opik + Jupyter Notebook (demo.ipynb + data_gen.ipynb)。

亮点：聚焦"评测+可观测性"这一 RAG 生产化关键缺口；Opik 100% 开源可自托管；适合学习评测指标设计。

局限：代码以 notebook 形式组织，README 极简（无架构图、无指标说明），工程化程度低。

28. llama-4_vs_deepseek-r1

中级Groq+OpenAI简历价值 3/5

用处：在同一 RAG 检索上下文中对比 Llama 4 与 DeepSeek-R1 的回答质量。

技术栈：LlamaIndex + Groq (双模型推理) + OpenAI o1 (作为 judge) + Opik (评测) + Streamlit。

亮点：同题对比两大热门开源模型；Groq 高速推理降低延迟；LLM-as-judge 评测方法（o1 做裁判）有展示价值。

局限：README 仅 359 token，无评测指标、无对比结论、无架构说明；需自行补充分析。

29. qwen3_vs_deepseek-r1

中级Opik简历价值 3.5/5

用处：对比 Qwen3 与 DeepSeek-R1 在同一 RAG 任务上的表现，两个模型均通过 Ollama 本地运行。

技术栈：LlamaIndex + Ollama (Qwen3 + DeepSeek-R1 双本地模型) + Opik (评测) + Streamlit + uv。

亮点：两个对比模型完全本地运行，零 LLM API 费用；与 #28 形成"云端 vs 本地"对照实验模板；本地模型推理显著降低复现门槛。

局限：README 同样极简，无评测维度和结果；本地运行大模型对显存/内存有要求。

八、高级/垂直场景（3个）

这类项目架构最复杂、功能最完整，代表 RAG 技术的产品级落地形态。

30. notebook-lm-clone ⭐⭐

高级4个付费API简历价值 4.5/5

用处：Google NotebookLM 的开源复刻——多格式文档上传、引用溯源回答、跨会话记忆、AI 播客生成。

技术栈：PyMuPDF (文档解析) + AssemblyAI (音频转写+说话人分离) + Firecrawl (网页抓取) + Milvus (向量库) + Zep (时序知识图谱记忆层) + Kokoro (开源 TTS) + Streamlit (三栏 NotebookLM 风格 UI)。

亮点：仓库中功能最完整的 RAG 应用——多格式摄入（PDF/文本/音频/YouTube/网页）、引用优先（每条回答带来源页码）、Zep 时序知识图谱记忆、AI 播客生成（多说话人 TTS）、模块化项目结构（src/ 下 8 个子模块）、有测试目录。

局限：需 4 个付费 API（OpenAI + AssemblyAI + Firecrawl + Zep）；复现成本高；组件多导致排错面广。

31. paralegal-agent-crew

中高级OpenAI+Firecrawl(可选)简历价值 4/5

用处：智能律师助理——上传 PDF 法律文档，通过高级 RAG + Web Search Fallback 提供带引用的综合回答。

技术栈：CrewAI + Milvus (binary quantization, embedded/Docker) + OpenAI + BGE-large-en-v1.5 + Firecrawl + Streamlit。

亮点：智能路由（自动评估 RAG 回答质量，不足时触发 Web Search）；Milvus 二值量化降本提速；法律垂直场景有辨识度；回答带 citations；Milvus WebUI 管理（:9091）。

局限：强依赖 OpenAI，无本地 LLM 替代方案；Python 3.13+ 要求较高。

32. context-engineering-workflow

高级5个云API简历价值 4/5

用处：研究助理——基于 CrewAI Flows 的 6 Agent 架构，并行聚合文档 RAG、对话记忆、网络搜索、外部 API 四路上下文，经评估过滤后合成带置信度的回答。

技术栈：CrewAI Flows + TensorLake (文档解析) + Milvus + OpenAI GPT (结构化输出) + Voyage Context 3 (嵌入) + Zep Cloud (记忆层) + Firecrawl (Web 搜索) + ArXiv (学术搜索) + YAML 配置驱动 + Streamlit。

亮点：6 Agent 协作（RAG/Memory/Web/Tool 并行 → Evaluator 过滤 → Synthesizer 合成）；Context Engineering 理念（多源上下文聚合+评估+合成）；扩展引用含相关性分数；Zep Cloud 持久化记忆跨会话；YAML 配置化 Agent/Task 定义工程化程度高；项目目录分层清晰。

局限：需 5 个付费云 API（TensorLake+Voyage+OpenAI+Zep+Firecrawl），几乎无法离线运行；复现成本最高。

十、选型决策总结

💰 零成本优先

选 llamaindex-mcp（唯一零付费 MCP 全栈）或 github-rag（代码仓库问答，可全本地）。两者均无需任何付费 API 即可完整运行。

🎯 差异化优先

选 rag-sql-router（SQL+RAG 双路由，匹配你的大数据背景）或 mcp-video-rag（唯一视频 RAG，检索→自动剪片）。

🏗️ 工程深度优先

选 notebook-lm-clone（8 模块产品级架构）或 context-engineering-workflow（6 Agent 并行 + Context Engineering）。

🔧 技术前沿优先

选 mcp-agentic-rag-firecrawl（MCP+Cursor+Agentic RAG）或 deepseek-multimodal-RAG（ColPali+Janus-Pro 本地多模态）。

📊 评测方法论优先

选 qwen3_vs_deepseek-r1（本地双模型对比 + Opik 评测）或 trustworthy-rag（TLM 置信度评分 + 幻觉治理）。

⚡ 性能优化优先

选 fastest-rag-milvus-groq（Milvus 二值量化 + Groq LPU，<15ms 检索）。适合在简历中写"RAG 系统性能调优"。

💡 给你的秋招建议：不要贪多。选择 1 个主项目（推荐 rag-sql-router 或 llamaindex-mcp）深入做 2-3 周，在原项目基础上做 2-3 个有说服力的扩展（如：用 TypeScript 重写前端、接入 MySQL 替换 SQL 引擎、加入评测管道、部署到 Docker），比浅尝辄止跑通 5 个项目更有简历价值。主项目跑通后，可以用 firecrawl-agent 的 Corrective RAG 思路做技术升级，形成"基础版→进阶版"的项目演进故事。
